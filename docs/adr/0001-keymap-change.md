# Keymap operations return a KeymapChange

Every keymap operation in `src/domain/keymap-ops.ts` (`assign`, `put`, `swap`, `move`, `clear`) returns a `KeymapChange`: `Partial<Record<Key, Shortcut | null>>` holding only the touched keys, where `null` frees a key. It is the single unit everything downstream works in. The keymap store writes a change as one `storage.sync` `set` / `remove` of `key.<K>` items. The undo record (`storage.session` `undo.keys`) is the same shape, filled with the touched keys' previous contents. Migrations and drag-to-swap produce changes too. We chose this over returning a whole new keymap and diffing it in the store, because per-key items with last-writer-wins sync make "which keys did this touch" the thing that matters. A diff would recompute what the operation already knows, and the undo record would have no direct source.
