# An older build keeps working when a newer schema arrives through sync

Chrome sync can hand a device running an older SpeedLink data written by a newer one, with a `meta.schemaVersion` higher than the older build knows. The older build keeps going: it reads tolerantly (unknown fields are kept, unreadable items look like free keys and stay in storage), writes normally, runs no migration steps and never lowers `schemaVersion` or migrates down. The cost falls on every future migration: it must stay readable by the previous version, so schema changes are additive only (new optional fields with defaults, new items). A breaking change would need a new item name rather than a rewrite in place. We chose this over freezing an outdated device read-only, because one stale computer locking a user out of their own shortcuts is worse than the constraint on migrations, and Chrome updates extensions quickly enough that mixed versions are short-lived.
